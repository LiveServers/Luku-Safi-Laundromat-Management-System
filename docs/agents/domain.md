# Domain docs

This repository uses a single-context layout.

Before exploring the codebase, read the root `GLOSSARY.md` and any relevant architecture decision records under `docs/adr/`. If either location is missing, continue. Domain modeling creates these docs as terms and decisions are resolved.

Use the glossary’s terms in issue titles, proposals, hypotheses, and test names. If a concept is missing, check existing project usage and raise genuine gaps during domain modeling.

If a proposal conflicts with an existing ADR, cite the ADR and explain which decision the proposal would reopen.
